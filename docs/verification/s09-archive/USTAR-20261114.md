# S09 ustar user export: local evidence (14 November 2026)

**Scope.** This file records evidence for `volume_core::ustar::from_archive`. It is a proposed converter from a verified S09 format-v1 archive to a POSIX ustar stream with pax `path` records. The format is decision D6 in [S09-BACKUP-DESTINATION-PROPOSAL.md](../../implementation/S09-BACKUP-DESTINATION-PROPOSAL.md) and stays proposed until the project owner decides it. This is host-level evidence plus an unchanged native volume gate. It is not S09 acceptance; the criterion stays open.
- Design, refusals and limits: [S09-BACKUP-ARCHIVE.md](../../implementation/S09-BACKUP-ARCHIVE.md), section "User export to ustar".
- The native archive slice this builds on: [NATIVE-20261113.md](NATIVE-20261113.md), merged with PR #318 as `7d9498a8`.

**AI review (not an independent human audit).** Three read-only workflow runs, each with a format lens and a safety lens; findings were to be checked by adversarial verifiers.
- Run 1, on the first ustar commit `c8b55305`: both lenses returned findings, but none of the verifiers finished.
- Run 2, also on `c8b55305`: the safety lens completed. Seven findings were verified and six confirmed. The format lens stopped at a usage limit.
- Run 3, on `15da41fa`: both lenses completed. Every finding was verified, and all five were confirmed.
- The final drive-form fix in `7191cd02` was not reviewed again; it was checked only by the tests and the mutant above.

Fixed in code:
- A path such as `C:x` or a collection named `C:` would leave the extraction directory on Windows. After run 2, a path that starts with an ASCII letter and `:` was refused.
- Run 3 showed that the Windows path parser takes any single UTF-16 code unit before `:` as a drive, not only A–Z, when such a drive exists. The source is cited in the spec, and the parser behaviour was not tested here. Python's `ntpath` takes any character there as a drive. The converter now refuses a path whose first character is followed by `:`.

Fixed in documentation:
- The exact bidirectional controls are now named.
- The empty-collection refusal is documented as conservative, and D6 now lists it.
- D6 no longer calls collections directories.
- Reader claims are limited to what was tested.
- The spec now states which tests need `python3` or `tar`.

Documented as not handled:
- On Windows: a later `:` (an alternate data stream), reserved device names, and trailing dots or spaces.
- Names that collide by case or by Unicode normalisation.

**Not run.**
- bsdtar or Windows `tar` as readers;
- extraction on Windows or macOS;
- a native stage that writes the export;
- CI on PR #325 (pending at the time of writing);
- KVM and hardware;
- an independent human audit.
